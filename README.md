# 두드리 랜딩 페이지

작업 위치: `C:\koss2026\landing`

HTML, CSS, JavaScript로 만든 독립형 반응형 랜딩 페이지입니다. 패키지 설치나 빌드가 필요하지 않습니다. 기존 서비스의 코드는 수정하지 않습니다.

## 실행

Python 3와 Node.js가 설치된 환경에서:

```powershell
cd C:\koss2026\landing
npm run dev
```

브라우저에서 **http://127.0.0.1:3100**을 엽니다. 실행한 터미널에서 `Ctrl+C`로 종료합니다.

Node.js 없이 `python -m http.server 3100 --bind 127.0.0.1`로 실행하거나, `index.html`을 브라우저에서 직접 열어도 됩니다.

## 서비스 연결

시작 버튼과 기능별 링크는 기존 앱의 `http://localhost:3000`으로 연결됩니다. 실제 기능을 이용하려면 루트의 `start-local.bat`로 서비스를 실행하세요.

배포 시 `index.html`의 다음 설정을 실제 서비스 주소로 바꾸고, 같은 파일의 기본 `href="http://localhost:3000/..."` 링크도 동일하게 변경하세요. 별도 API 키나 환경 변수는 필요하지 않습니다.

```html
<meta name="dudri-app-url" content="https://실제-서비스-주소">
```

정적 호스팅에는 `index.html`, `styles.css`, `journey.css`, `script.js`, `assets/`를 함께 올리면 됩니다. 폰트와 이미지가 모두 로컬에 있어 외부 CDN 요청은 없습니다.

### Vercel

`vercel.json`에 설치·빌드 없이 정적 파일을 제공하도록 설정했습니다. `.vercelignore`는 페이지와 해당 자산만 업로드하도록 제한합니다. 반드시 이 `landing` 폴더를 프로젝트 루트로 사용하세요. 프로젝트 전체를 올리는 설정이 아닙니다.

Computer Use 없이 Vercel 플러그인이나 공식 CLI로 배포할 수 있습니다. 계정 인증은 사용자가 `npx vercel login`으로 완료하거나 Vercel 플러그인을 설치·연결해야 합니다. 인증 파일이나 토큰을 프로젝트로 복사하지 않습니다. 실제 공개 배포 전에는 저장소 작업 규칙에 따라 승인을 받습니다. 현재 배포는 실행하지 않았습니다.

## 구성

- `index.html`: 서비스 소개, 화면 크기에 맞는 데스크톱·모바일 미리보기 전환, 기능 탭 4종, 모바일 화면 갤러리, 이용 방법, FAQ.
- `styles.css`: Figma와 기존 앱의 보라·청록 토큰, 반응형 레이아웃, 오로라·캐릭터·카드·마퀴 애니메이션.
- `journey.css`: 스크롤에 연결된 3장면 여행. 캐릭터 이동, 카드 교차 전환, 배경 시차, 연결선과 단계별 진행률이 실제 스크롤 위치에 따라 양방향으로 재생됩니다. 브라우저 주소창을 포함한 작은 뷰포트(`svh`) 기준으로 높이가 690px 미만(폭 600px 이하에서는 760px 미만)이거나 모션 정지·동작 줄이기 설정에서는 세 카드를 정적으로 보여줍니다.
- `script.js`: 탭 키보드 이동, 모바일 메뉴, 갤러리, 스크롤 효과, 화면이 보일 때만 동작하는 파티클, 모션 정지.
- `assets/`: 로고, 개별 캐릭터 PNG 2개, Figma 화면 7개, Pretendard 폰트와 라이선스.

스프라이트 시트를 사용하지 않습니다. 캐릭터는 Figma의 개별 노드를 투명 PNG로 내보냈으며, CSS 크롭 없이 사용합니다.

모바일에서는 본문과 터치 영역을 확대하고, 이용 방법 카드를 세로로 배치합니다. 폭 600px 이하에서는 Figma의 모바일 홈·커리어맵 이미지가 자동 선택됩니다. 갤러리는 손가락으로 좌우 스와이프할 수 있으며, 메뉴는 가로 화면에서도 내부 스크롤로 이용 가능합니다. 노치·홈 표시줄 안전 영역을 반영하고 브라우저 확대를 허용합니다.

## 확인

```powershell
npm run check
```

JavaScript 구문을 검사합니다. 기존 `frontend`의 Playwright와 Edge로 320·360·390·768·1024·1440·1920px의 레이아웃, 기능 탭, 화면 전환, 갤러리, FAQ, 메뉴, 모션 정지 및 동작 줄이기 설정을 검증했습니다. 스크롤 장면은 320·390·1440px에서 장면 전환, 캐릭터 이동, 역방향 재생 및 단계 버튼을 확인했고, 낮은 가로 화면·동작 줄이기 설정의 정적 전환도 확인했습니다. 로컬 검증 스크린샷은 Git에서 제외되는 `.preview/`에 저장합니다.

모바일 반응형 보완 후에는 Chromium 터치 에뮬레이션으로 320×568, 375×667, 390×844, 412×915, 600×960, 768×1024, 1024×768, 844×390을 확인했습니다. 실제 터치 이벤트를 통한 갤러리 스와이프, 메뉴·탭·FAQ 조작, 이미지 비율과 모바일 이미지 선택, 가로 넘침 및 장면·단계 버튼의 화면 내 표시를 검증했습니다. 추가로 320×844, 390×760과 740×390에서 경계 크기와 화면 회전도 확인했습니다. iOS Safari·Android 실기기 검증은 별도입니다.
